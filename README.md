# 🎂 Blow Candle Birthday · 吹蜡烛生日快乐

> 一个**零文案**的生日惊喜网页：打开就是一支在暗处摇曳的蜡烛，对着麦克风轻轻一口气就能把它吹灭；烛光散去后，粒子重聚成「生日快乐」。
>
> 纯原生 JavaScript + Canvas 2D 手写软件 3D 渲染 —— **无框架、无依赖、无构建、无网络请求**。

在线体验：**https://blow-candle-birthday.app.workbuddy.host/**

A zero-copy birthday surprise web page: a pink particle birthday cake that you blow out with your
microphone, then the particles re-form into "Happy Birthday". Vanilla JS, hand-written software 3D
rasterizer, no framework / no dependencies / no build step.

## 项目简介

这个项目要解决的是一个很窄但很具体的问题：**怎么把「请你吹蜡烛」这件事，做得不像一个说明书。**

常规做法是在页面上写「请对着麦克风吹气」「已吹灭！」——但生日礼物一旦出现操作提示，惊喜感就没了。
所以本项目的核心设计约束是三条：

1. **零文案** —— 整个页面不出现任何一个字。不提示怎么操作，也不反馈结果。
   引导完全交给**火焰本身**：它会周期性被一阵无形的风撩动，你靠近麦克风、轻轻呼气时它会明显偏移，
   形成"它有反应"的生物反馈。
2. **一口气就灭** —— 从开始吹气到蜡烛熄灭约 **0.17 秒**，正常距离轻轻一口气即可，
   不需要喊、不需要吹很久。
3. **不像玩具** —— 火焰、烟雾、火星都是三维公告板粒子，可以拖着转、可以缩放，
   熄灭时火苗会整体脱离烛芯飘散，而不是干脆地"消失"。

同时它对"误触发"很警惕：正常说话、唱歌、音乐、关门声、爆音都不应该吹灭蜡烛。

## 快速开始

本项目**没有构建步骤**，克隆下来就是一个可用的静态站点。

```bash
git clone https://github.com/WuShuoyuOvO/blow-candle-birthday.git
cd blow-candle-birthday
```

⚠️ **必须通过 HTTPS 或 `localhost` 打开。** `getUserMedia`（麦克风）只在浏览器的"安全上下文"下可用，
直接双击 `index.html`（`file://` 协议）会导致麦克风不可用。

本地起一个服务：

```bash
# 方式一：Python（无需安装任何东西）
python3 -m http.server 8080

# 方式二：Node
npx serve .
```

然后浏览器打开 <http://localhost:8080>。

**部署到线上**：这是一个纯静态站点，把仓库根目录直接扔给任意静态托管即可
（GitHub Pages / Vercel / Netlify / Cloudflare Pages / 任意对象存储 + CDN），
无需配置构建命令和输出目录。**唯一要求是必须能通过 HTTPS 访问。**

> 用 GitHub Pages 部署：仓库 Settings → Pages → Source 选 `Deploy from a branch`，
> Branch 选 `main` / `root`，保存后访问 `https://<你的用户名>.github.io/blow-candle-birthday/`。

## 使用说明

### 交互方式

| 操作 | 效果 |
|---|---|
| 对着麦克风**轻轻吹气** | 火焰明显偏斜并熄灭（约 0.17 秒） |
| **拖拽**（鼠标 / 单指） | 旋转视角，环绕观察蛋糕与火焰 |
| **双指捏合** / **滚轮** | 拉近拉远（距离 3.0 ~ 11.0） |
| **双击**（或手机双轻点） | 揭晓之后重新开始 |

无需任何点击或授权按钮：页面加载后会立即请求麦克风权限。若权限被拒绝，
会退化为**长按屏幕 0.34 秒**代替吹气，保证在无麦克风环境下依然可用。

### URL 参数

| 参数 | 说明 | 上限 |
|---|---|---|
| `to` | 祝福对象，聚字时显示为「祝 {to}」 | 12 字符 |
| `msg` | 附加留言，与 `to` 同时存在时显示为「{to} · {msg}」 | 16 字符 |
| `debug` | 设为 `1` 时左下角显示实时调试面板（帧率、麦克风特征值、状态机阶段、几何自检） | — |

生成一条送给小明的链接：

```
https://blow-candle-birthday.app.workbuddy.host/?to=%E5%B0%8F%E6%98%8E&msg=%E7%94%9F%E6%97%A5%E5%BF%AB%E4%B9%90
```

（参数值需要 `encodeURIComponent` 编码，浏览器地址栏可直接粘贴中文。）

### 调试面板

在链接后加上 `?debug=1` 后，左下角会出现一块等宽字体面板：

```
fps 60 q 1.00
mic OK
rms 0.2910 thr 0.0016
lowR 0.62 crest 3.8 flat 0.47 hf 0.07
air 1.00 breeze 0.80 cfm 70
blow YES str 1.00
health 0.00 phase out
flame 142 smoke 34 spark 0

```

其中 `geo ... PLANTED` 是**几何自检**：把粒子按径向距离分成"蛋糕本体"（`r > 0.20`）与
"蜡烛窄柱"（`r < 0.12`），比较蜡烛最低点与蛋糕装饰最高点，用于确认蜡烛确实埋在顶层里而不是悬空。

## 技术亮点

### 1. 手写软件 3D 光栅化（不引 Three.js）

引入 Three.js 会带来 ~600KB 的 CDN 依赖（且微信内置浏览器对第三方 CDN 的加载并不总是可靠）。
这个项目用的是**点云渲染**，本质上只需要一个透视投影，所以整套 3D 管线是自己写的，约 200 行：

- **轨道相机**：`yaw / pitch / dist` → 手算 `forward / right / up` 正交基，透视投影 `s = focal / z`。
  `focal` 按「高宽双向 fit」取小值，竖屏横屏都能完整取景。
- **背面剔除**：`dot(normal, point - eye) > 0` 的点直接丢弃。
  这一步是"立体感"的关键——没有它，点云看起来是一层半透明的空壳；有效剔除后才有实心物体的错觉，
  而且比做完整深度排序便宜得多。
- **光照**：兰伯特漫反射 + 边缘光 `(1 - |n·f|)^3` + 深度雾。光源方向挂在**相机坐标系**上
  （`-0.34f + 0.72u + 0.48r`），保证用户转到任何角度都有稳定的明暗关系，不会转到背面就一片死黑。

### 2. 着色分桶 + 计数排序：1.8 万粒子每帧只切 168 次样式

Canvas 2D 逐点设置 `fillStyle` 是最大的性能瓶颈。本项目把颜色**量化**为
`21 色调色板 × 8 明度档 = 168 个预生成 rgb 字符串`，每帧：

1. 对每个可见粒子算出 `bucket = palette * 8 + shade`（连续光照量化为离散档位）；
2. 用**计数排序**（O(n)，两遍扫描）把粒子归入桶，得到每桶的连续区间；
3. 绘制时整桶共用一个 `fillStyle`，只需 168 次样式切换。

### 3. 共享几何 + 共享种子：两层粒子无缝交叉淡入淡出

页面同时存在两套粒子集合：覆盖层（`veilSet`）与底层惊喜内容（`sceneSet`）。
如果它们各自生成、各自随机，淡出淡入时会明显看出"这是两个不同的东西"。

解决办法是让两者**完全同源**：共享同一份蛋糕几何（含蜡烛）、同一组初始散布坐标、
同一组随机种子，因此每一帧的轨迹逐粒子一致。`veil` 层 `opacity` 淡出的同时 `scene` 层淡入，
视觉上就是同一个物体在继续演化。

### 4. 吹气识别：为什么不能直接用音量阈值

最朴素的做法是「RMS 超过阈值就算吹气」，但它会被说话、音乐、关门声轻易触发。
本项目用了四路特征 + 两道防护：

| 特征 | 吹气的表现 | 说话/音乐的表现 |
|---|---|---|
| **时域 RMS** | 高于自适应环境噪声基线 | 也高 —— 所以**单独不够** |
| **低频能量占比** `lowRatio` | 高（气流噪声集中在 < 900Hz） | 低（元音/谐波分布更宽） |
| **频谱峰值比** `crest = max / mean` | 低（宽平稳噪声） | 高（有明显谐波峰） |
| **谱平坦度** `flat = 几何均值 / 算术均值` | 高（接近白噪） | 低（谐波结构） |

两道防护：

- **谐波否决**：`crest > 8 && 高频/低频能量密度比 > 0.45` 同时成立 → 判为人声/音乐，直接否决；
- **70ms 确认窗**：条件需**连续成立** 70ms 才触发，`_confirm` 上升 `dt`、下降 `2·dt`。
  爆音、关门、碰撞这类瞬时噪声永远攒不满确认窗。

**⚠️ 这里有一个关键陷阱：`getByteFrequencyData()` 返回的是 dB 压缩后的字节。**

直接拿这些 0~255 的字节去算峰值比和谱平坦度，人声和吹气会挤在一起无法区分
（实测峰值比只有 5.9，完全没有判别力）。必须先把字节**还原为线性幅值**：

```js
// minDecibels = -95, maxDecibels = -12（在 start() 中强制设置）
lin[v] = Math.pow(10, (minDb + (v / 255) * (maxDb - minDb)) / 20);
```

在 150~4000Hz 上基于线性幅值重算特征后，两者才真正分得开：

| 声音 | lowRatio | crest | flat | hfRatio | 判定 |
|---|---|---|---|---|---|
| 吹气 | 0.62 | 3.8 | 0.47 | 0.07 | ✅ 触发 |
| 说话 | 0.09 | 8.8 | 0.00 | 1.27 | ❌ 拒绝（低频占比 + 谐波两道都挡） |

### 5. 零文案 UX 是怎么做的

- **火焰是唯一的提示语言**：每 4~7 秒来一次"起风"（1.9s 的正弦包络），火苗与光晕整体顺风偏移；
  同时 `out.air`（阈下连续气流量级）会让火焰对**真实气流**连续响应——用户刚靠近或轻轻呼气就能看到摆动。
  这是"隐晦但明确"的操作提示。
- **全屏覆盖层**：`#veil` 是真 DOM 层（`z-index: 30`，不透明径向渐变），
  在吹灭并完成动画前完整遮住底层内容，所以打开页面看到的只有一支蜡烛，不会提前剧透。
- **结果也不说话**：熄灭 → 火焰飘散 → 覆盖层淡出 → 蛋糕粒子飞散 → 重聚成「生日快乐」，全程无文字反馈。

### 6. 自适应画质

统计最近 45 帧的平均帧时间，超过 27ms 就把粒子绘制密度 `quality` 下调 0.28（最多 2 档，下限 0.45）。
注意**只降低绘制采样密度，不减少物理粒子数**——视觉上仍然完整，只是略稀疏。

## 吹气识别参数调优

所有阈值集中在 `blow-detector.js` 顶部的 `DEFAULTS`：

| 参数 | 默认 | 含义 |
|---|---|---|
| `sensitivity` | `2.2` | 灵敏度总控，越大越容易触发 |
| `absFloor` | `0.0016` | RMS 绝对下限 |
| `floorMul` | `1.10` | RMS 相对环境基线的倍数下限 |
| `calibMs` | `600` | 开机环境噪声校准时长 |
| `lowRatio` | `0.20` | 低频（< 900Hz）能量占比下限 |
| `crestMax` | `20` | 峰值比上限（超过则判为乐音） |
| `flatMin` | `0.18` | 谱平坦度下限 |
| `harmCrest` / `harmHF` | `8` / `0.45` | 谐波否决的两个条件 |
| `confirmMs` | `70` | 需连续成立的时长 |
| `holdMs` | `100` | 条件消失后的保持时长 |

**调优方法**：开 `?debug=1`，观察吹气与说话时 `lowR / crest / flat / hf` 四组数值的分布，
据此调整。当前值在桩测试下的分离度为：吹气 `0.62 / 3.8 / 0.47 / 0.07`，
说话 `0.09 / 8.8 / 0.00 / 1.27`，中间余量充足。

需要更灵敏（例如手机离得远）：调高 `sensitivity`，或 `floorMul` 降到 `1.05`。
误触发偏多：调高 `confirmMs`（如 `110`）或 `lowRatio`（如 `0.28`）。

熄灭速度由 `app.js` 中的 `DRAIN` 控制（当前 `4.8`），
公式 `health -= (0.9 + 1.3 * strength) * DRAIN * dt`，强度保底 0.7。

## 测试

仓库自带一个**无头冒烟测试**，用桩 DOM、桩 Canvas 与伪 `AudioContext`
在 Node 里按帧数确定性驱动整个应用，无需浏览器即可验证全链路：

```bash
node test/smoke.js
```

它覆盖以下断言：

- 应用能正常启动、麦克风初始化成功；
- **轻吹气**在约 0.17 秒内熄灭蜡烛（`health 0.00` / `phase out`）；
- 完整链路走通 `veil → out → lift → cake → disperse → gather → text`；
- **说话被拒绝**（`blow=no`，验证谐波否决 + 低频占比）；
- **瞬时全频噪声被拒绝**（50ms 突发，验证确认窗）；
- 双击重来恢复正常（`health 1.00` / `phase veil`）；
- 几何自检输出 `PLANTED`（蜡烛埋在蛋糕顶层内）。

伪 `AudioContext` 通过 `global.__MODE__` 切换"吹气 / 说话 / 突发噪声"三种频谱形态，
从而在一遍运行中同时覆盖正例与两类反例。

4. **改动前先跑测试**：`node test/smoke.js`，确保全链路断言仍然通过。
   若你修改了识别逻辑，请在 PR 中附上 `?debug=1` 下改动前后的特征值对比。
5. **保持"零依赖"**：这是本项目的核心约束之一——不接受引入运行时依赖或构建步骤的改动。
   如果确实需要，请在 Issue 中充分论证。

一些特别欢迎的方向：

- 更鲁棒的吹气识别（当前是启发式规则，换成更轻量的模型需要论证体积代价）；
- 更多蛋糕造型 / 配色主题（`app.js` 的 `PALETTE` 与 `makeBirthdayCake()` 是切入点）；
- 无障碍改进（键盘操作替代、动效强度开关）；
- 真机兼容性反馈（尤其是各版本微信内置浏览器）。
